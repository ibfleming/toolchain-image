Both are **research records**: they explain the reasoning and cite sources, but they were
written for one developer's setup (WSL, a homelab), and the implementation has since moved on.
Where they disagree with the code, the code and the decisions below win.

## Decisions that differ from the research

| Topic                       | Research said                                         | Implemented                                                                                                                                                                                                                         | Why                                                                                                                                                                                                                     |
| --------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tool manifest location      | `mise.toml` at the repo root                          | `toolchain/mise.toml` (+ `toolchain/dev/` for dev-only tools)                                                                                                                                                                       | A root `mise.toml` would activate the whole image toolchain in contributors' shells; the root one holds only repo tooling                                                                                               |
| Tool exposure               | mise shims on `PATH`                                  | Resolved binaries symlinked into `/usr/local/bin`                                                                                                                                                                                   | Shims re-resolve versions from whatever `mise.toml` a workspace contains, reintroducing drift in CI                                                                                                                     |
| Egress firewall             | Copy Anthropic's reference `init-firewall.sh`         | **Not included**                                                                                                                                                                                                                    | Built for unattended `--dangerously-skip-permissions` runs, which the managed policy disables; it added significant complexity and flaky network tests. Egress control belongs to Claude Code's sandbox or the network  |
| `vscode` sudo               | Limit sudo to the firewall script                     | Passwordless sudo (dev container convention)                                                                                                                                                                                        | Follows from removing the firewall; the managed Claude policy remains the default but is advisory under sudo                                                                                                            |
| Dev-only tools              | Not specified                                         | Separate `toolchain/dev/` manifest, parity `ci ⊆ dev` still enforced                                                                                                                                                                | Keeps `ci` lean while letting `dev` add tools without breaking parity                                                                                                                                                   |
| Shell/prompt                | Not specified                                         | Modular zsh config, starship, k9s, one-dark theme                                                                                                                                                                                   | Batteries included; every part is overridable (see [customizing](../customizing.md))                                                                                                                                    |
| Release automation          | Tag-driven with a weekly rebuild                      | Same, plus git-cliff for changelog and notes                                                                                                                                                                                        | release-please only releases on new commits, which would stop weekly rebuilds that pick up OS security fixes                                                                                                            |
| Commit format               | Conventional Commits                                  | Enforced with commitlint (`config-conventional`, no body length limit); squash-merge, PR title = commit title, branch commits = body                                                                                                | Reference tooling instead of an in-house script                                                                                                                                                                         |
| Signing                     | Keyless (Sigstore)                                    | Keyless                                                                                                                                                                                                                             | Note: signatures are recorded in the public Rekor log, which reveals the repository name and image digests even for private repositories                                                                                |
| Personal config             | Dotfiles via VS Code's `dotfiles.*` clone             | **Not part of the platform**                                                                                                                                                                                                        | Personal setup is each developer's concern; the image and template neither require nor document a dotfiles integration, so the platform stays project infrastructure (#40)                                              |
| Dockerfile-pinned downloads | Version ARG + SHA-256 ARG per tool                    | mise verified by maintainer signature (vendored keys, pinned fingerprints); zsh plugins fetched by git commit                                                                                                                       | Renovate can bump a version but can't compute a checksum, so every bump needed a manual step; signatures and commit hashes make each update self-contained                                                              |
| Workflow supply chain       | Pin actions to commit SHAs (a Scorecard check)        | SHA pins, plus a jactionlint security audit in `make lint` (online checks in CI), an allowlist of action owners, Harden-Runner egress audit, CodeQL for workflows, OpenSSF Scorecard published, signed provenance on release assets | Pins alone don't catch template injection, cache poisoning, impostor commits or over-broad tokens; the audit runs locally too (#81)                                                                                     |
| Claude Code CLI             | Pinned, signature-verified native binary in the image | **Not included**; the image keeps the managed policy, the `~/.claude` volume and the VS Code extension                                                                                                                              | The extension runs its own bundled CLI, so the image's copy duplicated it at another version; dropping it removes a pin, a vendored key and a custom Renovate datasource, and stops tying the image to one AI CLI (#40) |
